# Verification ledger

This file separates code inspection, local cryptographic checks, Linux engine execution, and Esmeralda transactions. An accepted dry run is not a committed transaction. A fee-only success is a main-intent failure. Testnet commitments are evidence of execution on Esmeralda, not an audit or mainnet qualification.

## Pinned target and source

- Tari Ootle [v0.41.2 release](https://github.com/tari-project/tari-ootle/releases/tag/v0.41.2), published 2026-09-23; release archive preserved under `.upstream/source/` and excluded from this repository.
- Public indexer `https://ootle-indexer-a.tari.com` returned `version: 0.41.2` and `network: esmeralda`. Raw probe: `evidence/indexer-probe.json`.
- Template library `0.32.1`, Ootle engine/test tooling `0.41.2`, wallet crypto `0.43.0`, Ootle Rust client `0.23.0`, Tari crypto `0.23.2`; dependency resolution is pinned in `Cargo.lock`.
- Current WASM binary was 303,922 bytes. The live template ID and deployment receipt are recorded in `evidence/publish-receipt.json`.

The [published binary comparison](../evidence/template-binary-match.json) queried the indexer-verified template substate and SHA-256 hashed its decoded WASM. A **fresh Windows Rust 1.97.1** release build from the current source produced exactly the published 303,922 bytes and hash `818d0842257cb7af83d4ee1b7ed1b2b74ef537cc6074c2f924cfa1e114c0de54`. A fresh **Ubuntu WSL Rust 1.98.1** build produced 344,902 bytes and a different hash. The byte-identity claim is therefore tied to the Windows 1.97.1 toolchain; differing toolchains must not be treated as reproducible artifacts. The indexer's verified flag is still not independently checked consensus proof.

The published protocol uses Ootle's native [stealth resources](https://ootle.tari.com/guides/stealth-resources/) and the current source implementation. [Spend context](https://github.com/tari-project/tari-ootle/blob/v0.41.2/crates/template_lib_types/src/stealth/spend_context.rs) inspects one transfer; it does not expose an arbitrary private balance computation. `KeyAndScript` has a key escape path. A native output promise is a lower bound, not an exact budget. The component therefore verifies full input/output sets and independent Pedersen opening sums for all frozen roles and stages. The [fee model](https://ootle.tari.com/reference/fees/) can commit fee effects while the main call fails.

The observed missing-UTXO failure on the first pledge was a **client transaction construction bug**: Ootle cannot infer UTXO input addresses from an encoded component method argument. The ledger correctly refused the absent input. The client now adds each UTXO as an explicit transaction input; all four pledges subsequently committed. The first unsuccessful dry run remains at `evidence/pledge-alice-dry-run.json` only if the file was not overwritten; the final file is the successful rerun. Never interpret this as a chain rollback.

## Remaining qualification

The local engine has exercised boundary and replay cases; some additional Esmeralda adversarial equivalents, stale-indexer behavior, and capacity and cost above 32 pledges remain to be recorded. The indexer has returned `summary: null` for several committed transactions even though the submitting client received `Commit` receipts and the indexer-verified component/UTXO views showed the resulting state changes. Those saved receipts are local client evidence where the indexer view has not caught up. Missed-funding, partial-delivery and final audit owner refunds are committed, but no production or mainnet claim is made.

## Separate use-case PoCs — compilation and term checks only

The new exchange, audit, infrastructure, grant, and community-only template crates are separate from the published v1 above. All five built to WASM in Ubuntu WSL with the pinned dependencies; their distinct Ootle entry points were present in the resulting modules. Four `threshold-poc-core` tests passed for example budgets and encoding, funding modes, sponsor-role admission, and selected term validation.

These checks do not execute the Ootle engine or prove transaction, payment, or refund behavior. No PoC was deployed, and none inherits the v1 testnet qualification. The existing v1 client and recovery packages do not support their experimental version 100 terms. Detailed engine tests, adversarial transfers, client integration, recovery validation, and testnet execution remain unfinished. See [the template guide](campaign-templates.md).
